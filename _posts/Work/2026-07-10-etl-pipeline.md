## 요구사항

- 대용량 라벨 데이터 납품 전, 형식·값·무결성을 검증하는 객관적 품질검증 체계 구축
- 실제 작전 운용 환경에서 데이터 처리부터 라벨링까지 실시간으로 수행하는 파이프라인 구성
- 개발 AI 모델이 실전 항적 분류에 활용 가능한 수준의 분류 정확도 달성

## 문제 정의

| 구분 | 문제 |
|---|---|
| 데이터 통합 | 작전일지·레이더 신호·신호처리 결과가 서로 다른 기준으로 생성되어, 공통 고유 ID 부재로 통합이 어려움 |
| 품질 검증 | 대용량 라벨 데이터를 사람이 전수 검수하기 어려운 규모로, 검증의 객관성·일관성 확보가 어려움 |
| 운영 효율 | 신규 운용 환경 추가 시 데이터 처리부터 라벨링까지 장시간이 소요되어 효율성이 저하됨 |
| 모델 성능 | 실전 환경의 클래스 불균형으로 소수 클래스의 분류 정확도 확보가 어려움 |

## 문제 해결 — 데이터 처리 파이프라인

**[수집·통합] → [정제·보정] → [품질 검증] → [모델 개발·검증]**

각 단계를 데이터 처리(실무)와 문서 표준화(관리) 양측면에서 수행했습니다.

| 단계 | 수행 (실무) | 문서 (관리) |
|---|---|---|
| ① 수집·통합 | 서로 다른 기준으로 생성된 데이터를 변수 분석으로 복합 키를 식별해 매칭 기준을 확보하고, 통합 결과의 신뢰성을 검증 | 수집 가이드라인 수립, 요구사항 추적표·산출물 관리대장 작성으로 데이터 기준 정의 |
| ② 정제·보정 | 상황별 수기 기록 오류(자정 넘김·날짜 역전 등)를 앞뒤 데이터로 자동 감지·정정하여 검수 시간을 대폭 단축 | 정제·가공 가이드라인 수립으로 작업 표준을 정의하고 단계 간 일관성 확보 |
| ③ 품질 검증 | 산출 데이터의 다항목을 자동 점검하고, 검증 결과를 파이프라인 개선으로 환류하는 순환 구조 확립 | 검사 가이드라인·품질관리 체크리스트 기반 Cycle별 자가점검 및 3자 검증으로 품질을 객관적 산출물로 증빙 |
| ④ 모델 개발·검증 | 시계열 데이터를 동일 길이로 세그멘테이션하고 언더샘플링으로 클래스 균형을 맞춘 뒤, 다중 모델을 비교·검증하여 목표 분류 정확도 달성 | 프로그램 명세서·유스케이스 명세서·운용자 매뉴얼 작성으로 모델 활용 기반 마련 |
